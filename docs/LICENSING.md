# Лицензирование FluxCore (self-hosted продажа)

Лицензия проверяется **offline** — подписанным ключом (Ed25519), без
обращения к серверу продавца при каждой проверке. Это надёжнее для
self-hosted продукта (клиент не должен зависеть от доступности твоего
сервера лицензий) и проще в поддержке.

## Разовая настройка (продавец, один раз)

```bash
python manage.py generate_keypair
```

Выведет `LICENSING_PRIVATE_KEY` (храни в секрете, никогда не публикуй и
не клади в git) и `LICENSING_PUBLIC_KEY` (безопасно встраивать в код/
раздавать клиентам — это не секрет, только публичный ключ для проверки).

## Выпуск лицензии клиенту

```bash
python manage.py generate_license --customer "ООО Ромашка" --max-nodes 5 --days 365
```

- `--max-nodes` — не указывать = без ограничения по числу нод
- `--days` — не указывать = бессрочная лицензия

Команда выведет готовый лицензионный ключ — отправь его клиенту.

## Активация на стороне клиента (self-hosted инсталляция)

В `.env` клиента должен быть публичный ключ продавца:
```
LICENSING_PUBLIC_KEY=<публичный ключ, полученный от generate_keypair>
```

Затем клиент активирует свой ключ один раз:
```bash
python manage.py activate_license <полученный_лицензионный_ключ>
```

## Что ограничивает лицензия сейчас

- Максимальное количество нод (`max_nodes`) — проверяется при создании
  ноды через API (`NodeViewSet.perform_create`) и через админку
  (`NodeAdmin.save_model`).
- Срок действия (`expires_at`) — перепроверяется при каждой активации;
  для регулярной ревалидации без активации заново стоит добавить
  периодическую Celery-задачу, вызывающую
  `apps.licensing.services.revalidate_active_license()`.

## Что можно добавить далее

- Привязка лицензии к hardware fingerprint инсталляции (доп. защита от
  копирования одной лицензии на несколько серверов).
- Ограничение по количеству клиентов (`Client`) или активных подписок,
  а не только по нодам — если это более релевантная единица тарификации
  для твоей модели продаж.
